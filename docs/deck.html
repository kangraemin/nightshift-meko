Night Shift

On-call agents that never solve the same incident twice, even when the other shift solved it.

Repeats resolved: 55% → 71% from the agents' own memory;
~90% with the team's notes, at 42% of a wiki's tokens

The same page gets solved twice

  • Internal on-call teams split the night into shifts.
  • The engineer who fixed the 2 a.m. page writes it down in their own notes, if at all.
  • The next shift gets the same page and starts from the wiki again.
  • The wiki is half right: it describes last year's causes, not this week's.
  • Worse, a remembered fix can stop working. Applying it again wastes the first ten minutes of an outage.

Night Shift turns each verified fix into team memory, and keeps a ledger of which remembered fixes still work.

How it works

One page, end to end

  • Triage. The shift searches its own memory and the team's collective knowledge in Meko.
  • Check. Every hit is joined with the Postgres fix ledger: valid, retired, or unverified.
  • Investigate. The agent runs diagnostics. The Fixer only applies a fix to a target seen in evidence or memory.
  • Remember. A verified fix becomes a private memory, a postmortem artifact and a ledger row.
  • Learn from people. When the agent gives up, the on-call human's fix is stored the same way, marked as written by a person.
  • Share. At the end of the night the datapack owner promotes every fix the ledger still marks valid. The other shift finds them next time.
  • Forget on purpose. When a remembered fix fails, the ledger retires it and the Fixer refuses it from then on.

Postgres keeps memory honest

Promoted memories cannot be edited or deleted over MCP. Retrieval alone cannot tell a good memory from a stale one. So the ledger decides.

People stay in the loop

  • Review before sharing. A learned fix stays with its shift until a person approves it (nightshift.review approve). A rejected fix is retired, so the Fixer refuses it.
  • Fixes made by hand. When the agent gives up, the engineer's fix goes into Meko as that shift's memory, marked as written by a person. {{HUMAN_NOTE}}
  • Real alerts. An Alertmanager webhook runs the same triage on a live alert: what the team already fixed, who fixed it on which page, and which old fix the ledger says not to re-apply. It suggests; it never acts.

Limits and next steps

  • The incidents are simulated so that grading is exact. Real pages are messier.
  • One 8B local model, no paid API. A larger model solves more first-seen pages in both modes.
